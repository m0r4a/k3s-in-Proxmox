# Ansible

Configures VMs into a k3s cluster with Cilium networking and SeaweedFS
storage. Designed to work with the Terraform-generated inventory but can
run standalone with a manual inventory.

## Usage

```bash
# After terraform apply (generates inventory.ini)
ansible-playbook -i inventory.ini site.yml

# Standalone (using the example inventory)
ansible-playbook -i inventory-example.ini site.yml
```

## Design

Terraform generates `inventory.ini` with infrastructure facts (IPs,
users, SSH key path, control plane IP, cluster CIDRs). All ansible
configuration (cilium versions, install URLs, reboot policy) lives in
committed `group_vars/all.yml`. This separation lets ansible run
without terraform by writing a manual inventory.

## Roles

| Role | Target | Purpose |
| --- | --- | --- |
| `common` | all | Package update, base packages, SSH hardening, sudo config, reboot |
| `k3s` | k3s_cluster | Swap off, kernel modules, sysctl for k3s |
| `k3s_server` | control_plane | k3s server, Cilium, Helm, Flux, Hubble |
| `k3s_agent` | worker | k3s agent join |
| `storage` | storage | Data disk, firewall, Docker, SeaweedFS |

## Role naming

The terraform role string uses hyphens (`control-plane`, `worker`,
`storage`). The ansible group names use underscores (`control_plane`,
`worker`, `storage`). The inventory template maps between them.

## group_vars

| File | Source | Purpose |
| --- | --- | --- |
| `all.yml` | Committed | Ansible config (cilium, helm, flux URLs, versions) |
| `control_plane.yml` | Committed | Extra packages for control plane |
| `k3s_cluster.yml` | Committed | kernel-modules-extra for k3s nodes |
| `storage.yml` | Committed (create from example) | SeaweedFS config, credentials |

## Inventory vars (generated by Terraform)

The `inventory.ini` `[all:vars]` section provides infrastructure facts:
`k3s_control_plane_ip`, `k3s_cluster_cidr`, `k3s_service_cidr`,
`cluster_admin_user`, `cluster_admin_home`,
`ansible_ssh_private_key_file`.

## Security

VM SSH hardening (disable root, key-only auth) is applied by the
`common` role. Controlled by `ssh_hardening_enabled: true` (default).
Set to `false` in `group_vars/all.yml` to disable.

Storage node firewall is optional. Set `seaweedfs_firewall_enabled:
true` and `seaweedfs_allowed_cidr: "your-subnet/24"` in
`group_vars/storage.yml` to restrict SeaweedFS ports to the cluster
subnet.

See [security.md](../security.md) for full documentation.
